# Reward abuse and analytics limitations

Default campaigns exclude their owner's address and current payout address from rewards. The merchant can explicitly disable this protection or select Open, QIE ID verified, or Disabled rewards atomically at creation. Policy changes are public events. Test invoices are immutably marked at creation, settle actual token amounts normally, and never earn rewards. They are not free simulations. Browser demo data remains labelled and separate from the on-chain invoice flag.

This is not Sybil resistance. Linked wallets, changing payout wallets, colluding merchants, recycled payment funds and unmarked test invoices cannot be reliably identified by wallet matching. A merchant can mislabel activity. No verified identity implementation is enabled. Lifetime reward caps are per public address and campaign, not per human. Merchant funding bounds losses; reservation protects existing credits, not campaign profitability. Merchants should use small testnet budgets, retain the default self-payment guard, and review campaign economics.

Classification snapshots are emitted with each payment. Gross counts/volume include all observed payments and are labelled as such. Production volume/count and unique/repeat public-address counts exclude explicitly marked tests and direct owner/current-payout self-payments, even if the merchant disabled reward self-protection. Policy-eligible counts are distinct from reward-earning counts: an eligible wallet can receive zero because of dates, pause, cap or exhausted budget. Exclusion reasons are 1 self, 2 identity unavailable, 3 disabled, 4 test, 5 no campaign; 0 means policy eligible. Legacy events without classification remain unclassified rather than retroactively asserted eligible. Alias fields uniqueCustomers/repeatCustomers are retained for SDK compatibility; UI labels refer only to public wallet addresses.

An open-mode payout change is checked at payment time, not invoice creation. A former payout wallet is not detectable as linked. Identity integration must not be marketed as eliminating collusion. Next steps: consented pilot review, independent economics assessment, officially verified identity credentials if documented, and transparent cohort exclusions. Do not collect facial data, identity documents or off-chain profiles.
